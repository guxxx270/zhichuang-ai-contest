# 隐盾 · 贴给大模型前先脱敏（个人赛 · 工具赛道）v0.2

> 任何文本贴进去，客户姓名、机构名、手机、座机、身份证、资金账号 / 银行卡、邮箱、内网地址、密钥、金额，自动换成 `<客户_1>` 这样带类型的语义标签；拿到大模型的回答，一键换回原文。纯本地规则，不联网、不装模型、即插即用。

## 为什么

大赛红线：「未脱敏的客户身份信息、交易持仓数据、内部财务数据不得上传至未经许可的公网大模型」。员工日常用 AI 最容易踩的就是这一步——把微信原话、邮件、工单、日志直接贴过去。人工逐处找、逐处改，又慢又容易漏，改完还得自己记着哪个是哪个。隐盾把「贴之前先过一道门」变成几秒钟的习惯。

## 三种用法

| 用法 | 怎么开 | 适合 |
|---|---|---|
| 网页 | 双击 `启动隐盾.command`（Mac）/ `启动隐盾.bat`（Windows），或 `streamlit run app.py` | 日常问答：① 贴原文 → 脱敏 → 复制去问 AI；② 把回答贴回来 → 还原 |
| 剪贴板一键 | 复制原文 → 双击 `剪贴板脱敏.command` / `.bat` → 粘贴给 AI；复制 AI 回答 → 再双击 → 粘贴的就是还原后的文字 | 最快：不用开网页，只用 Python 标准库 |
| 命令行 / 嵌入 | `python cli.py redact|restore|check|clip …`；`from yindun.privacy import Redactor, Session` | 批量处理材料目录、提交前检查、嵌进其他智能体 |

网页版首次双击会自动建虚拟环境并装 Streamlit（约 1 分钟），之后秒开；只在本机 `127.0.0.1` 监听，关闭了 Streamlit 的使用统计上报。

### 网页版要点

- **多轮一致**：同一会话里多次脱敏共用一张映射表——同一客户、同一号码（`139 1234 5678` 和 `13912345678` 算同一个）始终同一标签，新出现的接着编号；任何一轮的回答都能还原。侧边栏可导出映射表，隔天在「② 还原」里载入。
- **原文对照**：结果区可切到「原文对照」，原文里要被换掉的内容标红，发出去前扫一眼。
- **疑似遗漏**：没有上下文的 6～9 位数字（可能是账号）不自动换，会提示，一键确认后一起脱敏。
- **容错还原**：模型把标签改写成 `〈客户_1〉`、`【客户_1】`、`\<客户\_1\>`、`&lt;客户_1&gt;`、`<客户1>`、`客户_1`、全角，照样还原；映射表里没有的标签（多半是模型编的）单独提示。
- **可调**：自定义客户 / 机构名单、不脱敏白名单（公司热线等）、按类型开关（例如要模型算比例时临时关掉「金额」）、文件拖入（txt / md / csv / log / json / docx 等）。

### 命令行

```bash
python cli.py redact 材料.txt                       # 输出脱敏文本；映射表写到 材料.map.json（含原文，只留本机）
python cli.py redact 材料目录/ --out 材料目录_脱敏/   # 批量，目录下所有文件共用一张映射表
python cli.py restore 回答.txt 材料.map.json         # 还原
python cli.py check 待外发目录/                      # 只检查：发现明文敏感信息时退出码 1，可挂在外发 / 提交前
python cli.py clip [--new]                          # 剪贴板一键脱敏 / 还原；--new 开新会话
# 通用选项：--names / --orgs / --keep 名单文件（一行一个）；--map 接着已有映射表编号；--off 金额,机构；--hint 加「请原样保留标签」提示
```

### 嵌入其他程序

```python
from yindun.privacy import Redactor, Session

s = Session(Redactor(names=["张三"]))        # 多轮对话用 Session；单次用 Redactor().redact()
r = s.redact("客户王建国先生手机 13912345678")
r.text      # '客户<客户_1>先生手机 <手机_1>'
s.restore("请回电〈客户_1〉").text  # '请回电王建国'
```

同源规则已在团队作品「需知」中作为安全模块使用（需求原话、底稿、代码摘录进模型前一律先过隐盾）。

## 规则清单

| 类型 | 识别方式 | 示例 → 标签 |
|---|---|---|
| 客户 | 「客户 / 投资者」后的姓名，「姓 + 先生 / 女士」，紧挨在手机 / 账号 / 证件 / 邮箱 / 座机前的姓名；同事称谓（王总、张老师）不算 | 客户王建国先生 → 客户<客户_1>先生 |
| 机构 | 「客户 / 机构 / 投资者」后的 XX 公司 / 集团 / 基金 / 资管 / 投资 / 私募 / 证券 / 期货 / 银行 / 信托 / 保险 / 资本；「客户想做期货」「客户大多是银行」这类泛称不算 | 机构：华东某某投资公司 → 机构：<机构_1> |
| 手机 | 1 开头 11 位，含 +86、空格、短横分段 | 139 1234 5678 → <手机_1> |
| 电话 | 区号 - 号码（- 分机） | 021-61234567 → <电话_1> |
| 身份证 | 18 位、校验出生日期，含 6-8-4 分段 | → <身份证_1> |
| 账号 | 10～19 位数字、4-4-4-4 银行卡；6～9 位要有「资金账号 / 客户号 / 交易编码 / 卡号」上下文 | 资金账号：88123456 → 资金账号：<账号_1> |
| 邮箱 | 标准邮箱 | → <邮箱_1> |
| 内网地址 | 10.x / 172.16～31.x / 192.168.x | → <内网地址_1> |
| 密钥 | `api_key / token / secret / password / 密码 / 口令 = …`（只换值，留键名）、连接串口令、私钥块、`sk-` / `ghp_` / `AKIA` / `LTAI` / JWT / Bearer | api_key=sk-… → api_key=<密钥_1> |
| 金额 | 千分位大数、带「元」、¥ 开头；「万 / 亿」前要有权益、浮亏、入金、转出等资金语境；单价（元/吨）、成交量（万手）不换 | 浮亏 125 万元 → 浮亏 <金额_1> |
| 自定义 | 侧边栏名单 / `--names --orgs`；白名单 `--keep` | 任意 |

设计要点（对照腾讯玄武「隐私不上云」的能力框架）：语义保持（标签带类型）；信息还原（同一实体同一标签、多轮一致、容错还原）；开集指定（自定义名单与白名单）；端侧执行（纯规则，不联网）。

## 测试与评测

- `pytest -q`：37 项，覆盖十类实体、与需知同源的补漏用例、凭据与金额、多轮会话、容错还原、文件读取、命令行批量与 check 退出码、网页（Streamlit AppTest）走一遍示例 → 脱敏 → 还原。
- `python tools/eval.py`：评测集 `data/eval_cases.json`（全部虚构），成绩单见 `data/eval_report.md`。开发集 48 条：敏感项检出 100%（83/83），业务词误伤 0/72，无敏感文本误改 0/16，往返一致与容错还原（8 种改写）100%；**留出集**（规则定稿前写好、定稿后只跑一次）16 条：检出 96%（24/25，漏的是「付」姓不在姓氏表），误伤 0。单条平均约 0.03 ms，1 万字一次约 4 ms。

## 已知边界

- 没有上下文的裸姓名、外号（老张）、复姓、不在常见姓氏表里的姓：用自定义名单。
- 机构名前没有「客户 / 机构 / 投资者」：用自定义名单。
- 住址不识别；「万 / 亿」前没有资金语境的数字不当金额。
- 持仓明细表、财务报表不在处理范围——这类数据本就不该贴给公网模型。隐盾的定位是「贴之前过一道门」，不是替你把报表脱敏后上传。
- Windows 上的剪贴板一键（PowerShell 读写剪贴板）尚未实机验证；网页版与命令行不受影响。
