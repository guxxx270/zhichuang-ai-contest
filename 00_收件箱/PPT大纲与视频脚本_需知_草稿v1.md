## 二、Demo 视频脚本（4 分 30 秒，1080P 录屏 + 旁白；全部虚构数据）

| 时间 | 画面 | 旁白（口语） |
|---|---|---|
| 0:00～0:20 | 首页：Logo、六个技能标签、KPI 行 | 这是需知，一个需求分析工作台。技术部收到的需求，不管是微信三句话、会议纪要还是邮件，扔进来，五分钟出一份能开工的需求。 |
| 0:20～0:50 | 选样例①（资管运营微信原话），点"需知，开工"；规则引擎瞬间出结果 | 资管运营的同事在微信里说：净值日报加一列变动，风险指标也放进去，客户版也要。就这三句话。点开工——没填模型 Key 也能跑，规则引擎毫秒级。 |
| 0:50～1:30 | 问清页：12 条待确认清单滚动；点开两条看"不问会怎样"和默认假设；右侧确认消息，点下载 | 第一步问清。它先问的是期货问题：变动的基准是结算价还是收盘价？客户版要脱敏哪些字段？每条都告诉你不问会怎样，给了默认假设。右边这段确认消息，直接发给业务。 |
| 1:30～1:50 | 在两条答复框里填"以结算价为准""客户版去掉集中度"，点"按业务答复重算" | 业务答了两条，其它按默认。重算，需求单、工时、架构同步更新。 |
| 1:50～2:15 | 写单页：业务版一页纸 → 切技术版，滚到用户故事、数据字典 | 第二步写单。业务版一页纸给业务签字，技术版用户故事、验收标准、数据字典给开发，每条回链原话。 |
| 2:15～2:45 | 估量页：三路并列（模型 / 规则模板 / 历史记录）→ 规则模板的六维雷达与分维工时 →（有 Key 时）模型工作项表的分工与逐项证据 | 第三步估量，三路并列、不混算。规则模板按六维打分，以前约 81 小时、现在约 50 小时，标着未校准；旁边是 3 条相似历史需求的当时估算与实际工时。接了模型，它按工作项逐项估以前和现在，每项写理由、引用原话作证据，标出 AI 能做、AI 做人审、人必须做，再按分工给出交付建议。 |
| 2:45～3:20 | 定架页：复用发现一句话；数据地图表（可复用 / 需申请 / 需计算标签）；决策 D1 展开；下载 ADR | 第四步定架。报表平台可承载；数据地图告诉你每个数据从哪个系统哪个接口取、时效够不够：净值来自估值核算 T+1，客户信息要向客户管理系统申请字段权限，变动列要自己算。四项要 IT 拍板，选项、建议、影响都列好，ADR 一键下载。 |
| 3:20～3:45 | 出样页：原型页滚动，切"客户版"，内部字段消失；切手机版 | 第五步出样。业务看得见的需求：这就是改完的净值日报，客户版自动去掉内部字段，手机版也有。 |
| 3:45～4:10 | 一本账页：状态改"已交付"；对账表单填实际人天 9、勾 AI 协同，提交；看板数字变化（有模型估时才算估算偏差，无 Key 时看「规则模板参考 vs 实际」） | 第六步对账。需求全程在一本账上，交付后填实际人天；有模型估时的，偏差自动算出来、进入历史记录供下次参考。看板是部门的需求经营：谁提得多、澄清几轮、估得准不准、AI 预计省多少。 |
| 4:10～4:30 | 隐盾页：样例 ① 没有敏感信息（脱敏 0 处），展开页内「看一个脱敏示例」，或插一段样例 ③ 邮件里客户姓名、资金账号、手机号被换成标签的画面；回到首页，字幕"先问清，再开工" | 最后一道门隐盾：原话、底稿、代码进模型前都在本地脱敏。需知——先问清，再开工。 |

录制要点：Chrome 全屏 1920×1080，隐藏书签栏；提前跑一遍让样例①的答复、对账数据就位；旁白用同一人；字幕用 PPT 同一字体；片尾放团队名与部门。若现场路演，用同一脚本，最后加一段"请评委口述一个需求"（真实交互附加分），口述功能事先测好麦克风。
