## 0. 选题的尺子

1. **服务对象**是投资、资管、研究员（哪怕是后台，也要能说清"投研因此得到什么"）。
2. **技术部能做、材料拿得到**：Demo 全用虚构数据也讲得通，不依赖拿不到的内部系统。
3. **不撞车**：不与研伴重叠，不与公司已有的"打标签涨跌"系统相似。
4. **有"人人都有智能体"的味道**，评委五维（业务价值 25 / 创新 20 / 落地 20 / 可复制 20 / 安全合规 15）都能拿到分。
5. **现场能演**：3 分钟内评委看得懂、能插手互动（附加分）。

## 1. 六个候选

### ① 「问数管家」—— 投研取数 Data Agent　★ 最贴今天的口径

- **一句话**：研究员 / 投资经理 / 资管经理用一句话要数据，管家先把口径问清，再生成查询、出表出图，附口径说明和数据来源；技术部从"人肉写 SQL 跑数"里解放出来，取数需求变成台账，口径沉淀成指标字典，越用越准。
- **痛点**：技术部日常第二件事——各部门取数 / 报表需求。投研等数取数要排队，口径来回确认，同一需求反复提，老同事一走口径就丢。
- **技能**：问数（自然语言 → 查询，带澄清）｜口径本（指标字典 / 语义层，每次确认过的口径自动沉淀）｜出图（图表 + 一段解读，对应通知里"自动化研报图表生成"的例子）｜订阅（一次取数一键变成定时报表推送）｜隐盾（行级权限 + 脱敏 + 留痕，复用研伴）。
- **Demo**：一个虚构数仓（行情、结算、产品净值、虚构持仓），预置 8 个投研常问的问题（"近一月各品种基差走势""某产品本周净值回撤最大的三天原因"），现场评委随便问。
- **参考**：已在库 Shopee / 数势 / 容联云；第四批新增 腾讯 DataBuddy、云器 Data Agent、喜马拉雅 ChatBI、网易数帆 DataAgent、阿里云 Quick BI、腾讯云 WeData。
- **五维**：业务价值 5 ｜ 创新 3 ｜ 落地 4 ｜ 可复制 5 ｜ 安全合规 4 → **85**
- **风险**：ChatBI 市面上很多，创新分靠"口径沉淀 + 订阅 + 权限脱敏"来拿；准确率是命门（语义层 + 澄清 + 结果校验三道保险）；真实数据权限敏感，Demo 全虚构。
- **与研伴的关系**：研伴答"规则和研报"，问数管家答"数据"，互不重叠；可以是研伴的一个技能，也可独立成品。

### ② 「数据哨兵」—— 投研数据质量巡检 Agent

- **一句话**：每天行情、结算、净值、持仓数据落库后自动巡检——缺失、跳变、口径不一致、与交易日历 / 合约规则冲突——晨会前给投研一份"数据健康报告"，异常自动解释并定位到上游任务；问题先于研究员被发现。
- **痛点**：投研用错数据比没数据更可怕；技术部天天被追问"这个数对不对""为什么和昨天不一样"；巡检靠人肉 SQL 和老师傅的经验。
- **技能**：巡检（规则 + 统计基线）｜解释（结合上游任务日志、交易日历、合约换月解释异常）｜追溯（血缘定位到任务和表）｜晨报（健康报告推送）｜留痕。
- **Demo**：虚构数据管道，注入 6 类故障（漏日、涨跌停外跳变、单位错、重复、迟到、换月未切），现场触发一个看它抓出来并解释。
- **参考**：第四批 网易数帆 DataAgent、腾讯云 WeData、腾讯大数据自治、飞轮 AI-Ready 数据基础设施；第三批 字节 SRE Agent（降噪思路）。
- **五维**：4 ｜ 4 ｜ 5 ｜ 4 ｜ 5 → **87**
- **风险**：单独做略"小"，评委可能当成运维小工具；**更适合作为 ① 的一个技能**（问数管家先保证数是对的，再回答）。
- **与研伴的关系**：无重叠。

### ③ 「投研工具箱」—— 内部系统 MCP 网关，"人人都有智能体"的底座　★ 最有技术范

- **一句话**：把行情、结算、风控、研报库、报表、OA 等内部系统封装成一套标准工具（MCP），统一鉴权、脱敏、限流、审计；任何部门的人在公司 AI 平台或任何 Agent 框架里，都能安全地"调用公司系统"，30 分钟拼出自己的智能体。研伴、问数管家、守门员都跑在它上面。
- **痛点**：每做一个智能体都要重接一遍系统、重做一遍权限；业务部门自己搭的智能体接不到内部数据；谁调了什么没人管。大赛主题就是"人人都有智能体"，缺的正是这层底座。
- **组件**：工具注册（一个系统一份 YAML）｜网关（鉴权 / 脱敏 / 审计 / 限流）｜工具市场（按部门可见）｜装配台（选工具 + 写提示词 = 一个智能体）｜隐盾。
- **Demo**：虚构 5 个内部系统 → 注册成工具 → 现场用装配台 3 分钟拼出"资管经理助手"（查净值 + 查限仓 + 写日报）→ 审计页显示每一次调用与脱敏。
- **参考**：第四批 腾讯 DataBuddy Agent Runtime、荣耀 YOYO 智能体平台、淘宝闪购 Agent 平台化、钉钉 AI 助理平台、MCP / A2A / ANP 协议对比、从 MCP 到 Agent 集成；在库 中软融鑫 Harness、池中 NoDesk 可控 Agent。
- **五维**：4 ｜ 5 ｜ 3 ｜ 5 ｜ 5 → **87**
- **风险**：平台型，决赛高管可能觉得抽象、看不到直接业务成效；工程量最大；必须用一个故事讲（"资管经理 3 分钟拼出助手"），否则像基础设施汇报。
- **与研伴的关系**：研伴是前台产品，工具箱是后台底座，可以打包成"一前一后"两个作品讲一个故事。

### ④ 「需求翻译官」—— 投研需求 → 原型 → 验收 Agent

- **一句话**：投研用业务语言提需求（"我要一个跟踪各品种基差的页面"），翻译官追问澄清、生成需求单、可点的原型页、测试用例和验收清单，开发拿到的是"能直接干"的需求；上线后自动出验收报告。
- **痛点**：技术部与投研之间"说不清、改不完"，需求反复、验收扯皮，小需求排队几周。
- **技能**：澄清｜写单｜出原型（可点的 HTML）｜出用例｜验收。
- **Demo**：现场请评委一句话提需求 → 3 分钟出需求单 + 原型 + 用例。
- **参考**：池中 好未来 PRD→上线、小红书 PRD→代码直出、大模型辅助需求代码开发；在库 蚂蚁 Vibe Coding。
- **五维**：4 ｜ 4 ｜ 4 ｜ 4 ｜ 4 → **80**
- **风险**：原型生成 / Vibe Coding 很多人做，创新一般；成效难量化。

### ⑤ 「值班搭子」—— 交易 / 行情 / 柜台系统智能运维 Agent

- **一句话**：告警降噪、故障定位、值班问答、应急手册秒答；成效讲"交易不中断、值班时间省一半"，服务的是投资 / 资管的交易连续性。
- **五维**：4 ｜ 3 ｜ 3 ｜ 4 ｜ 4 → **72**
- **风险**：要真实日志 / 监控数据才有说服力，Demo 全虚构打折；偏纯内部。参考见池 A 组。

### ⑥ 「变更守门员」—— 上线变更风险 Agent（昨天已选，构思 v1 已写）

- **一句话**：读变更单 + diff + SQL / 配置，对照规范与历史故障，30 秒出风险评级、影响面、检查清单、时窗建议、回退预案；高危拦下，人做最后一步。
- **五维**：4 ｜ 4 ｜ 5 ｜ 4 ｜ 5 → **87**
- **风险**：纯技术内部流程，离"服务投研"最远；决赛高管可能觉得离业务远。材料最全（构思 v1 + 第三批 13 份参考）。
