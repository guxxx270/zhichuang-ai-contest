# 需知 · Demo 视频旁白稿（草稿 v1）

> 成片 4:19，1920×1080 · 30fps · H.264 + AAC，字幕已烧录（同名 .srt 另附）。旁白为微软神经语音「晓晓」（edge-tts 合成），需要真人配音时按下表时间轴照念即可；演示所用需求、系统与数据全部虚构。
> 录制环境：本机启动需知，模型按 `.env` 配置在后台增强；等待模型的时段已剪去。重录方法见提交清单。

|---|---|---|
| 0:00–0:07 | 片头：需知 · 需求分析智能体，七个技能标签 | 这是需知，一个需求分析智能体。交给它一堆话，拿回一份能开工的需求。 |
| 0:07–0:25 | 痛点卡：资管运营的微信原话、技术部来回追问，三个痛点依次出现 | 比如资管运营在微信上发来三句话：净值日报加一列变动，风险指标也放进去，客户版也要。技术部要来回问好几轮，工时全凭经验估，像结算时点、夜盘这些期货口径，最容易漏掉。 |
| 0:25–0:38 | 首页选样例①（微信原话）→ 点「需知，开工」→ 规则初稿秒出，状态框显示模型在后台增强 | 我们把这段原话贴进来，点开工。不到一秒，规则引擎先出了初稿；要是配了模型，还会在后台接着补充，页面不用干等。 |
| 0:38–1:03 | 问清：需求要素、待确认清单（🌾 期货口径在前）、右侧确认消息 | 第一步，问清。先抽出需求要素，再对照期货 IT 追问知识库，列出要确认的问题，按影响大小排好。排最前面的就是期货口径：按结算后还是收盘价算？变动跟谁比？每条都写清楚，不问会怎样、默认怎么做。右边这段确认消息，可以直接发给业务。 |
| 1:03–1:24 | 在前三题填业务答复 → 「按业务答复重算」→ 顶部「本次变更」卡片 | 业务只用回答有异议的三条：以结算后为准，夜盘计入下一交易日；跟上一交易日结算价比；客户版去掉集中度。点一下重算，需求单、工时和架构就一起更新了。页面顶上还会列出这一版改了什么，哪些要重新确认。 |
| 1:24–1:37 | 写单：业务版一页纸 → 切技术版（用户故事、验收标准、数据字典） | 第二步，写单。业务版就一页纸，拿去签字。技术版里有用户故事、验收标准、数据字典和接口草案，每条都能找到对应的原话。 |
| 1:37–1:56 | 估量：三路依据并列（独立模型估时 / 规则模板参考 / 历史记录），工作项与依据 | 第三步，估量。三路依据摆在一起：模型把需求拆成工作项，人工开发和 AI 协同各要多少工时，每项都给出理由和证据。规则模板和历史记录单独列着，不混着算，负责人一看就能核对。 |
| 1:56–2:18 | 定架：数据地图（可复用 / 需申请 / 需计算）、IT 决策与 ADR 下载 | 第四步，定架。数据地图把每个数据项，对应到系统、数据域、接口和时效。净值从估值核算系统取，客户信息要申请字段权限，变动这一列要自己算。要 IT 拍板的事，选项、建议、影响都列好了，一键生成架构决策记录。 |
| 2:18–2:30 | 出样：原型页 → 客户版（集中度列消失）→ 手机版 | 第五步，出样。能点的原型，直接给业务看。切到客户版，内部字段自动拿掉了；手机上也能看。 |
| 2:30–2:48 | 一本账：版本记录（任选两版对比）→ 需求经营看板 | 第六步，对账。每条需求从受理到交付，都记在一本账上。每一版分析都留着，随便挑两版就能对比。交付以后填上实际工时，看板就能算出各部门的需求量、澄清轮次和估算偏差。 |
| 2:48–3:02 | 样例⑤（同一提出方的周报需求）→ 问清里 🧠 沿用上次口径 | 接着，同一位同事又提了个周报需求。上次答过的结算时点、客户版，直接沿用，带个大脑图标；周报跟谁比，按周重新问，不照搬日报。 |
| 3:02–3:18 | 样例⑥（投研晨会纪要）→ 纪要直通车识别 3 条 → 拆成 3 条分别受理 | 晨会纪要里，往往夹着好几条需求。纪要直通车认出了三条，一键拆开，每条分别问清，分别记进一本账。 |
| 3:18–3:45 | Jira 需求评估：示例导出 14 条 → 汇总与柱状图 → XZ-1040、XZ-1036 详情 | 写好的 Jira 工单也能评。把一个迭代导出来传上去，按六个技术维度打分，算出传统工时和 AI 编码工时，跟原始预估比一比；差得多的会直接标出来；碰到交易链路的，单独提示风险。 |
| 3:45–4:06 | 样例③（邮件夹带客户姓名、资金账号、手机号）→ 隐盾：脱敏 3 处、沙箱策略表 | 最后是隐盾。这封邮件夹着客户姓名、资金账号和手机号，进模型之前，都在本地换成了标签。能碰哪些数据，写在一份沙箱策略里；每次用模型都留审计，不连生产数据库。 |
| 4:06–4:18 | 片尾：四个入口、一条流水线、一本账；换三张表即可复制；先问清，再开工 | 不管从网页、企业微信、接口还是 MCP 进来，走的都是同一条流水线、同一本账。需知，先问清，再开工。 |
