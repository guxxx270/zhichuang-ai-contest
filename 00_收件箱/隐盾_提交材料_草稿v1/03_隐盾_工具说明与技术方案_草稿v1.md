## 1 概述

### 1.1 一句话

隐盾是一个本地小工具：任何文本贴进去，客户姓名、机构名、手机、座机、身份证、资金账号与银行卡、邮箱、内网地址、密钥、金额，自动换成 `<客户_1>`、`<手机_1>` 这样带类型的语义标签；拿到大模型的回答，再一键换回原文。纯规则，不联网，不装模型。

### 1.2 用在哪里

- 营业部、客服把客户来电、微信原话转给研究员或丢给大模型写回复。
- 技术部同事把告警日志、配置片段、报错堆栈贴给大模型排查问题。
- 任何人要把邮件、工单、会议纪要交给公网或公司外的大模型做总结、润色、翻译。

这些场景的共同点：原文里夹着客户身份信息、账号、内网地址或密钥，而真正要问的问题并不需要这些原值。

### 1.3 对照工具赛道的评分要点

| 评分要点 | 隐盾怎么做到 | 可以当场核对的证据 |
|---|---|---|
| 即插即用 | Mac / Windows 双击启动；剪贴板模式和命令行只用 Python 标准库；不需要账号、模型和网络 | `启动隐盾.command` / `.bat`、`剪贴板脱敏.command` / `.bat` |
| 交互流畅 | 一个页面两步：① 贴原文 → 脱敏 → 复制；② 贴回答 → 还原。示例一键填入；原文对照、映射表、疑似遗漏都在结果区切换 | 单条脱敏页面显示用时约 0.2 ms；评测集单条平均约 0.03 ms |
| 明显缩减重复耗时 | 示例里 9 处敏感信息，人工要逐处找、改、记对应关系、回答里再逐处换回，约 36 次手工操作；隐盾固定 6 次操作，与敏感项多少无关 | 操作次数见 2.3；节省时间【待填写：试用实测】 |

## 2 痛点与价值

### 2.1 红线

大赛通知（公司公告〔2026〕第 0047 号）的合规要求写得很清楚：

> 严禁将未脱敏的客户身份信息、交易持仓数据、内部财务数据上传至未经许可的公网大模型。

这条也是公司日常的安全红线。问题在于，员工用 AI 最顺手的动作就是「直接贴」：微信原话、邮件、工单、日志原样复制，粘贴，发送。

### 2.2 人工脱敏的三个难处

1. **容易漏。** 手机号会写成 `139 1234 5678`、`+86 139-1234-5678`；身份证会按 6-8-4 分段；银行卡按 4 位一组；密钥藏在日志和数据库连接串里。人眼扫一遍，很容易放过去。
2. **改完还不回来。** 把姓名改成「客户 A」、账号改成「某账号」，大模型的回答里也是「客户 A」。要用这段回答，得自己记住谁是谁，再一处处改回去；多轮对话里编号还容易乱。
3. **在线工具不放心，装模型又太重。** 网上的脱敏服务本身就是一次外发；本地跑一个识别模型，对日常问一句话的场景太重，用不起来。

### 2.3 隐盾带来的变化

以 Demo 示例「客户来电转研究所」为例（虚构）：一段 5 行的营业部转发记录，含 9 处敏感信息（2 个人名、1 个机构名、手机、座机、资金账号、邮箱、2 笔金额）。

| 步骤 | 人工处理 | 用隐盾 |
|---|---|---|
| 发出去之前 | 逐处找出 9 处 → 逐处改写 9 处 → 记下 9 条对应关系 | 粘贴 → 点「脱敏」→ 复制（3 次操作） |
| 拿到回答之后 | 回答里有 9 处代号，逐处换回原文 | 粘贴回答 → 点「还原」→ 复制（3 次操作） |
| 合计 | 约 36 次手工操作，敏感项越多越多 | 6 次操作，与敏感项多少无关 |
| 漏改风险 | 靠人眼 | 规则识别 + 原文对照标红核对 + 疑似遗漏提示 |
| 耗时 | 【待填写：试用实测】 | 【待填写：试用实测】 |

价值归结为三点：第一，员工用 AI 的第一步就合规，安全红线落到一个几秒钟的动作上；第二，标签带类型，大模型仍然知道「这是一位客户、一个手机号」，回答质量基本不受影响；第三，回答拿回来能一键还原，脱敏不再意味着「用起来更麻烦」。

## 3 功能总览

### 3.1 一条数据流

图：F01_flow 隐盾数据流与本机边界

出本机的只有标签化文本。原文、映射表（标签 → 原文的对应关系）和还原后的回答都留在本机：网页版的映射表只在会话内存里，关页面即清空；需要隔天还原时，用户主动导出到本机。

### 3.2 三种用法

| 用法 | 怎么开 | 适合谁 | 依赖 |
|---|---|---|---|
| 网页版 | 双击 `启动隐盾.command`（Mac）/ `启动隐盾.bat`（Windows） | 日常问答；要看原文对照、要多轮对话 | Python 3.9+、Streamlit（首次自动安装） |
| 剪贴板一键 | 复制原文 → 双击 `剪贴板脱敏.command` / `.bat` → 粘贴给大模型；复制回答 → 再双击 → 粘贴就是还原后的文字 | 不想开网页，追求最快 | 只用 Python 标准库 |
| 命令行 / 嵌入 | `python cli.py redact / restore / check / clip`；`from yindun.privacy import Redactor, Session` | 批量处理材料目录、外发前检查、嵌进其他智能体 | 只用 Python 标准库 |

三种用法共用同一个规则引擎 `yindun/privacy.py`。同源规则已在团队作品「需知」中作为安全模块使用：需求原话、底稿、代码摘录进模型前一律先过隐盾。

### 3.3 能力清单

- **10 类敏感信息**：客户、机构、手机、电话（座机）、身份证、账号、邮箱、内网地址、密钥、金额；另有自定义名单。
- **语义标签**：`<类型_编号>`，同一实体全文同一标签；同一号码的不同写法算同一实体。
- **多轮一致**：同一会话共用映射表，新出现的实体接着编号，旧实体沿用旧标签。
- **容错还原**：模型把标签改成 `〈客户_1〉`、`【客户_1】`、`\<客户\_1\>`、`&lt;客户_1&gt;`、`<客户1>`、`客户_1`、全角写法，照样还原；映射表里没有的标签单独提醒。
- **疑似遗漏提示**：没有上下文的 6～9 位数字不自动换，提示用户确认。
- **可调**：自定义客户 / 机构名单、不脱敏白名单、按类型开关、发送前「请原样保留标签」提示的开关。
- **文件读取**：txt、md、csv、log、json、yaml、ini、conf、sql、xml、html、eml 与 Word（.docx），单个文件 5 MB 以内。

## 4 快速上手

### 4.1 环境

- 操作系统：macOS 或 Windows（网页版与命令行在 macOS 上实测；Windows 启动脚本按公司常见环境编写，【待填写：Windows 实机验证结果】）。
- Python 3.9 及以上（推荐 3.12）。网页版另需 `streamlit>=1.50`，由启动脚本首次运行时自动安装到工具目录下的 `.venv`；命令行和剪贴板模式不需要安装任何第三方包。

### 4.2 网页版

1. 双击 `启动隐盾.command`（Mac）或 `启动隐盾.bat`（Windows）。首次会创建虚拟环境并安装依赖，约 1 分钟；之后秒开。
2. 浏览器自动打开 `http://localhost:8501`（只在本机 `127.0.0.1` 监听）。
3. ① 贴原文 → 点「脱敏」→ 复制结果去问大模型；② 把回答贴回来 → 点「还原」。

也可以手动运行 `streamlit run app.py`。内网不能直连 PyPI 时，先配好公司 pip 镜像。

### 4.3 剪贴板一键

1. 选中要发给大模型的原文，复制。
2. 双击 `剪贴板脱敏.command`（Mac）/ `剪贴板脱敏.bat`（Windows）。窗口提示「已脱敏 N 处」，剪贴板里已经是脱敏后的文字（开头带一句保留标签的提示）。
3. 粘贴给大模型。拿到回答后复制回答，再双击一次，窗口提示「已还原 N 处」，剪贴板里就是还原后的文字。

剪贴板模式的映射表存在本人目录 `~/.yindun/clip.map.json`（文件权限仅本人可读写），多轮对话接着编号；开新话题时在命令行运行 `python cli.py clip --new`。

### 4.4 命令行

```bash
python cli.py redact 材料.txt                       # 输出脱敏文本；映射表写到 材料.map.json
python cli.py redact 材料目录/ --out 材料目录_脱敏/   # 批量：目录下所有文件共用一张映射表
python cli.py restore 回答.txt 材料.map.json         # 还原
python cli.py check 待外发目录/                      # 只检查：发现明文敏感信息时退出码为 1
python cli.py clip [--new]                          # 剪贴板一键
```

通用选项：`--names` / `--orgs` / `--keep` 指定名单文件（一行一个）；`--map` 接着已有映射表编号；`--off 金额,机构` 关掉某些类型；`--hint` 在脱敏文本最前面加「请原样保留标签」提示。

实测（虚构材料，3 个文件）：

```text
$ python cli.py redact 材料 --out 材料_脱敏
[隐盾] 告警日志.log → 材料_脱敏/告警日志.log：9 处
[隐盾] 客户来电.txt → 材料_脱敏/客户来电.txt：9 处
[隐盾] 第二轮.md → 材料_脱敏/第二轮.md：4 处
[隐盾] 共 3 个文件，换掉 22 处
[隐盾] 敏感项 19 个（密钥 3、账号 3、手机 2、内网地址 3、客户 3、邮箱 1、电话 1、金额 2、机构 1），用时 1.4 ms；映射表 → 材料_脱敏/隐盾映射表.map.json（含原文，只留本机）
$ python cli.py check 材料              # 退出码 1
[隐盾] 检查完成：发现 22 处明文敏感信息
$ python cli.py check 材料_脱敏          # 退出码 0
[隐盾] 检查完成：未发现明文敏感信息
```

22 处里有同一客户、同一号码跨文件重复出现，合并后是 19 个敏感项，共用一张映射表。

### 4.5 嵌入其他程序

```python
from yindun.privacy import Redactor, Session

s = Session(Redactor(names=["张三"]))        # 多轮对话用 Session；单次用 Redactor().redact()
r = s.redact("客户王建国先生手机 13912345678")
r.text                                       # '客户<客户_1>先生手机 <手机_1>'
s.restore("请回电〈客户_1〉").text            # '请回电王建国'
```

### 5.9 技术部场景：日志与配置

图：S09_ops 运维日志：连接串口令、密钥、令牌与内网地址

点「新会话」清空映射表，再点「系统告警排障」示例：内网地址、数据库连接串里的账号口令、`api_key=` 后的值、GitHub 令牌、客户姓名、银行卡号、手机号都换掉了，共 9 处 5 类。键名（`api_key=`、`token:`、`jdbc:mysql://`）原样保留，大模型仍能看懂这是哪一项配置，照样能帮忙排查。

### 5.10 疑似遗漏

图：S10_suspect 疑似遗漏：没有上下文的 8 位数字只提示

原文「他另一个号 12345678 也被冻结了」里的 8 位数字前后没有「账号」之类的上下文，可能是账号，也可能只是编号。隐盾不自作主张，只黄底提示「疑似遗漏」；点「确认是账号，一起脱敏」后按账号换掉。同一句里的「资金账号：88123456」有上下文，直接换掉。

### 5.11 侧边栏设置

图：S11_sidebar 侧边栏：会话映射表、自定义名单、白名单与类型开关

- **会话映射表**：显示条数；「导出」下载 `.map.json`（含原文，只存本机）；「新会话」清空映射表、原文与回答。
- **自定义名单**：没有上下文的裸姓名、复姓、外号、机构简称，一行一个加进来，整词替换。截图中加了「陈晓东」「欧阳明」。
- **不脱敏白名单**：公司客服热线、自家公司名等公开信息，不换。
- **脱敏类型**：10 类默认全开。要让模型帮忙算比例、看金额时，可以临时关掉「金额」。
- **保留标签提示**：开关脱敏文本开头的那句提示。

隔天还原：在「② 还原」展开「用导出的映射表还原」，载入导出的 `.map.json`。

## 6 识别规则详解

### 6.1 十类规则一览

| 类型 | 识别方式 | 示例 → 标签 |
|---|---|---|
| 客户 | 「客户 / 投资者」后的姓名；「姓 + 先生 / 女士」；紧挨在手机、账号、证件、邮箱、座机前的 2～3 字姓名 | 客户王建国先生 → 客户<客户_1>先生 |
| 机构 | 「客户 / 机构 / 投资者」后的 XX 公司 / 集团 / 基金 / 资管 / 投资 / 私募 / 厂 / 证券 / 期货 / 银行 / 信托 / 保险 / 资本 | 机构：华东某某投资公司 → 机构：<机构_1> |
| 手机 | 1 开头 11 位，含 +86、空格、短横分段 | 139 1234 5678 → <手机_1> |
| 电话 | 区号 - 号码（- 分机） | 021-61234567 → <电话_1> |
| 身份证 | 18 位，校验出生年月日，含 6-8-4 分段 | 110101 19900307 1234 → <身份证_1> |
| 账号 | 10～19 位数字；4-4-4-4 银行卡（可再接 1～3 位）；6～9 位要有上下文 | 资金账号：88123456 → 资金账号：<账号_1> |

| 自定义 | 名单（客户、机构或任意类型）整词替换；白名单整词放过 | 任意 |

### 6.2 设计取舍：难点在「不误伤」

1. **分段号码先认。** 身份证 6-8-4、银行卡 4-4-4-4 先于手机号匹配，否则分组号码会被拆成几段，各漏一截。
2. **短账号要上下文。** 6～9 位数字单看可能是 300 手、日期、编号。只有跟在「资金账号 / 资金账户 / 客户编号 / 客户号 / 交易编码 / 账号 / 账户 / 卡号」后面才换，且只换数字、保留上下文词。没有上下文的 6～9 位数字进入「疑似遗漏」提示，8 位日期（如 20261024）不提示。
3. **金额要资金语境。** 千分位大数、带「元」的金额、¥ 开头的金额直接换；「万 / 亿」不带「元」时，前 8 个字里要有权益、浮亏、入金、出金、转出、余额、保证金、申购、赎回等资金词才换。「螺纹 3650 元/吨」是行情单价，「成交 300 万手」是成交量，「市场规模 1.2 万亿」没有资金语境，都不换。
4. **机构名过滤泛称和动作。** 「客户想做期货」「客户大多是银行」「客户为期货公司」只是意愿、泛称或动作，换了反而抹掉期货语境。规则剥掉后缀看主体：是「这家 / 中小 / 外资」这类泛称，或以「想 / 做 / 交易 / 大多」这类动作词开头，就不当机构名。
5. **同事称谓不当客户。** 「找王总 13812345678」里的王总是同事，只换号码；「客户王总」点明了是客户，照常换。
6. **姓氏表与停用词。** 只认常见姓氏开头的姓名；姓氏字开头的常用词和行情词不当姓名，如「客户周报」「客户黄金持仓」「客户白天来电」；名字里不含「的 / 要 / 是」这类虚词。
7. **凭据只换值、留键名。** `api_key=<密钥_1>`、`"password": "<密钥_1>"`，模型仍知道这是哪一项配置。值只认 ASCII 字符，「密码：请联系管理员重置」不动；英文 `token` 后要跟冒号或等号，「Invalid token provided」不动。
8. **号码归一。** `139 1234 5678`、`+86 139-1234-5678`、`13912345678` 算同一实体、同一标签；还原时统一成第一次出现的写法。
9. **按出现先后编号。** 多遍跑完后按标签在文中首次出现的先后重排编号；多轮会话沿用的旧标签不动。

## 7 技术实现

### 7.1 规则流水线

图：F02_engine 规则流水线与容错还原

脱敏分七遍，每一遍只碰原文里还没被换掉的部分（已换成的标签不含会被后续规则误认的内容）：

1. 自定义名单（含其他类型的自定义词），长词先换；白名单里的词一律放过。
2. 技术凭据：私钥块 → 连接串口令 → 各类令牌 → 键值对与 Bearer。凭据里常有数字和 @，先换掉免得被拆成账号或邮箱。
3. 号码：身份证 → 银行卡 → 手机 → 邮箱 → 长账号 → 内网地址 → 座机。
4. 短账号（有上下文的 6～9 位）。
5. 金额：千分位 / 带元 / ¥；再看「万 / 亿」的资金语境。
6. 机构（上下文 + 泛称、动作词过滤）。
7. 姓名：「姓 + 先生 / 女士」→「客户 / 投资者 + 姓名」→ 挨着号码标签的姓名。

最后按出现先后重排编号。还原时只做一遍正则替换：先把模型改写过的 8 种写法归一成 `<类型_编号>`，再查映射表换回原文；映射表里没有的标签原样保留、单独提醒。一遍替换保证换回去的原文不会被再次替换（例如原文里恰好含有标签样文字）。

### 7.3 接口

| 接口 | 说明 |
|---|---|
| `Redactor(names, orgs, keep, kinds, terms)` | 构造规则引擎。`names` / `orgs`：自定义客户与机构名单；`terms`：其他类型的自定义词，如 `{"账号": ["12345678"]}`；`keep`：白名单；`kinds`：要换的类型，默认全部 10 类 |
| `Redactor.redact(text, start=None, known=None)` | 返回 `RedactResult(text, mapping, counts)`。`start`：各类型已用到的编号，新标签接着编；`known`：原文 → 已有标签，同一原文沿用 |
| `Session(redactor, mapping)` | 多轮会话：`redact()` 累积映射表；`restore()` 用累积的映射表还原 |
| `restore_detail(text, mapping, wrap=None)` | 容错还原，返回 `RestoreResult(text, restored, fixed, unknown)`；`wrap(原文, 标签)` 可定制换回去的样子（网页用它给还原处上色） |
| `suspects(redacted)` | 脱敏后的文本里还剩的可疑项（没有上下文的 6～9 位数字） |
| `PROMPT_HINT` | 「请原样保留标签」提示语 |

### 7.4 依赖与运行环境

- 规则引擎、命令行、剪贴板模式只用 Python 标准库（`re`、`json`、`zipfile`、`argparse`、`subprocess` 等）。
- 网页版依赖 `streamlit>=1.50`（实测 1.63.0；从源码包全新安装时装到的 1.66.1 也跑通了 37 项测试），测试依赖 `pytest>=8.0`。
- 剪贴板读写：macOS 用系统自带的 `pbpaste` / `pbcopy`；Windows 用 PowerShell 的 `Get-Clipboard` / `Set-Clipboard`；其他系统用 Python 自带的 tkinter。
- 性能：评测集单条平均约 0.03 ms，最长约 0.18 ms；1 万字一次脱敏约 4 ms（本机 CPU）。

## 8 安全与合规设计

| 措施 | 做法 | 在哪里 |
|---|---|---|
| 不联网 | 规则引擎纯本地计算，不调用任何模型或外部服务 | `yindun/privacy.py` |
| 只听本机 | 网页服务只在 `127.0.0.1` 监听，局域网里的其他人打不开 | `.streamlit/config.toml`：`server.address` |
| 不上报 | 关闭 Streamlit 使用统计 | `.streamlit/config.toml`：`gatherUsageStats = false` |
| 实测无外联 | 用 Playwright 记录一次完整演示（示例脱敏 → 填入回答 → 还原）的浏览器请求，144 个请求全部指向 127.0.0.1 | 2026-10-24 本机实测 |
| 映射表不落盘 | 网页版映射表只在会话内存；关页面或点「新会话」即清空；导出按钮提示「含原文，只存本机，不要外发」 | `app.py` |
| 落盘时收紧权限 | 命令行生成的 `.map.json` 与剪贴板模式的 `~/.yindun/clip.map.json` 权限设为 0600（仅本人可读写） | `cli.py`：`_save_map` |
| 不写日志 | 工具不写日志文件，原文、映射表、回答都不留痕 | — |
| 上传限制 | 文件拖入上限 5 MB；只收文本类与 .docx | `config.toml`：`maxUploadSize`；`yindun/files.py` |
| 拿不准只提示 | 没有上下文的数字不自动换，也不自动放过：列为疑似遗漏，让人确认 | `suspects()` |
| 发出前可核对 | 「原文对照」把要被换掉的内容标红，其余就是会原样发出去的文字 | 网页结果区 |
| 定位清楚 | 隐盾是「贴之前过一道门」。持仓明细表、财务报表这类数据本就不该贴给公网模型，隐盾不处理表格、也不建议脱敏后上传 | 规则与边界页、本文第 11 章 |

需要说明：隐盾是规则工具，不能保证 100% 识别。它降低的是「顺手贴出去」的风险，不替代公司的数据防泄漏（DLP）与审批制度。使用者发送前仍应扫一眼「原文对照」。

## 10 推广与落地

### 10.1 三步推广

1. **个人自用。** 下载即用：双击网页版或剪贴板一键。适合所有日常用 AI 的同事，尤其是营业部、客服、研究所和技术部。
2. **部门共享名单。** 部门把常用客户、机构简称整理成名单文件（一行一个），网页侧边栏粘贴或命令行 `--names` / `--orgs` 引用，补上裸姓名、简称这类规则认不出的写法。名单本身是敏感信息，只在部门内部受控分发。
3. **平台前置过滤。** 把 `Redactor` / `Session` 嵌进公司 AI 平台或内部智能体的网关：出站前脱敏，回答回来后还原。团队作品「需知」已经这样使用同源规则（需求原话、底稿、代码摘录进模型前先过隐盾）。另外可把 `cli.py check` 挂在材料外发或代码提交之前，发现明文就拦下。

### 10.2 推广时要注意

- 规则需要按公司实际补充：姓氏表、机构后缀、内部系统的账号格式、内网域名。规则集中在 `yindun/privacy.py` 一个文件，补一条规则配一条测试用例。
- 宣传口径要实事求是：隐盾降低「顺手贴出去」的风险，不保证 100% 识别；发送前看一眼「原文对照」。
- 公司内网不能直连 PyPI 时，网页版首次安装依赖需要配置公司 pip 镜像；命令行与剪贴板模式不受影响。
- 推广效果用数据说话：试用期间统计使用次数、拦截处数（可由使用者自报）和反馈的漏检写法，持续补规则与评测集。【待填写：试用部门、人数与周期】

| `python cli.py check 文件或目录` | 只检查，发现明文敏感信息时退出码为 1 |
| `python cli.py clip [--new] [--no-hint]` | 剪贴板一键脱敏 / 还原 |
| `--names / --orgs / --keep 名单文件` | 自定义客户、机构名单与白名单（一行一个，# 开头为注释） |
| `--off 金额,机构` | 关掉某些类型 |
| `--hint` | 脱敏文本开头加「请原样保留标签」提示 |

## 附录 B 常见问题

**问：大模型把标签改了写法，还能还原吗？**
答：能。`〈客户_1〉`、`【客户_1】`、`\<客户\_1\>`、`&lt;客户_1&gt;`、`<客户1>`、`客户_1`、全角写法都认，统一换回原文，页面上会显示「纠正写法 N 处」。模型自己编出来、映射表里没有的标签会原样保留并提醒。

**问：关了页面，映射表还在吗？**
答：不在。网页版映射表只在会话内存里。需要隔天还原，先在侧边栏「导出」映射表，再在「② 还原」里载入。导出的文件含原文，只存本机，不要外发。

**问：多轮对话里，同一个客户会不会每轮编号都不一样？**
答：不会。同一会话共用一张映射表，同一客户、同一号码（不同写法也算）始终是同一个标签，新出现的实体接着编号。

**问：能处理 Excel 里的持仓明细吗？**
答：不处理。持仓明细、财务报表这类数据本就不该贴给公网模型。隐盾的定位是「贴之前过一道门」，处理的是日常问答里夹带的客户信息、账号、地址和密钥。

**问：隐盾会联网吗？会把我的文本发到哪里吗？**
答：不会。规则引擎纯本地计算；网页服务只在本机 127.0.0.1 监听，并关闭了 Streamlit 的使用统计。一次完整演示的浏览器请求经抓包核对，全部指向 127.0.0.1。

**问：识别错了怎么办？**
答：没认出来的，加进侧边栏的自定义名单；不该换的（如公司热线），加进白名单；某一类整体不想换（如金额），在类型开关里关掉。发送前看一眼「原文对照」，红色以外就是会发出去的原样文字。

**问：和团队作品「需知」是什么关系？**
答：同源规则。隐盾是独立的小工具，任何人都能单独用；需知把同一套规则作为安全模块，嵌在需求原话、底稿和代码摘录进模型之前。独立版在此基础上补了技术凭据、带单位的金额、多轮会话、容错还原和疑似遗漏提示。
