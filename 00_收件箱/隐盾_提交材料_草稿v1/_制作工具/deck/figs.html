数据流与本机边界出本机的只有标签化文本；原文与映射表始终留在本机内存

本机 · 隐盾（127.0.0.1，不联网）
公网 / 公司外的大模型
① 原文
微信、邮件、工单、日志、Word
客户王建国先生，手机 139 1234 5678
② 规则引擎
名单 → 凭据 → 号码 → 金额 → 机构 → 姓名 → 按出现先后编号；同一实体同一标签
③ 脱敏文本
客户<客户_1>先生，手机 <手机_1>
只发标签化文本
④ 大模型作答
看得懂「这是一位客户、一个手机号」，回答照常；看不到原值
映射表（会话内存）
<客户_1> → 王建国
<手机_1> → 139 1234 5678
多轮共用 · 可导出到本机 · 关页面即清空
⑤ 回答（含标签）
模型常把标签改写：〈客户_1〉 【客户_1】 \<客户\_1\> 客户1……
贴回本机
⑥ 容错还原
8 种写法归一 → 查映射表 → 换回原文；对不上的标签单独提醒
⑦ 可直接用的回答
给王建国先生的回复要点……回电 139 1234 5678；原文、映射表、回答都没有离开本机
规则引擎只用 Python 标准库；网页版另需 Streamlit（只听 127.0.0.1、关闭使用统计）。命令行与剪贴板模式不需要任何第三方依赖。

规则流水线与容错还原先认最确定的，再认需要上下文的；每一遍只碰原文里还没换掉的部分

1
自定义名单
裸姓名、机构简称整词先换；白名单里的词一律放过
2
技术凭据
私钥块、连接串口令、sk- / ghp_ / AKIA / JWT；api_key=、密码： 只换值
3
号码
身份证 → 银行卡 → 手机 → 邮箱 → 长账号 → 内网地址 → 座机（分段写法先认）
4
短账号
6～9 位只在「资金账号 / 客户号 / 交易编码」后才换
5
金额
千分位、带元、¥；万 / 亿要资金语境；单价、成交量不换
6
机构
客户 / 机构 / 投资者 + XX 公司…；泛称、动作词过滤
7
姓名
先生 / 女士、客户后、挨着号码；行情词与同事称谓过滤
标签怎么编
类型 + 编号：<客户_1> <手机_2>。同一号码不同写法（139 1234 5678 / +86 13912345678）算同一实体； 新标签按在文中第一次出现的先后编号；多轮会话接着上一轮的最大编号往后编，旧实体沿用旧标签。
语义保持：模型知道是谁、是什么多轮一致一遍替换，不会二次替换
拿不准的只提示
没有上下文的 6～9 位数字（可能是账号，也可能是编号）列为「疑似遗漏」，用户确认后按账号脱敏；不自作主张。
容错还原：8 种写法都认
<客户_1>〈客户_1〉【客户_1】\<客户\_1\> &lt;客户_1&gt;<客户1>客户_1＜客户＿１＞
归一成 <类型_编号> → 查映射表 → 换回原文；只换映射表里有的，模型自己编出来的 <客户_9> 原样留着并提醒人工核对。
发送前提示
脱敏文本开头自动加一句「形如 <客户_1> 的标记是占位符，请原样保留」，从源头减少改写。
原文客户王建国先生（手机 139 1234 5678）浮亏 125 万元
→
发出去的客户<客户_1>先生（手机 <手机_1>）浮亏 <金额_1>
→
模型回答（改了写法）请回电〈客户_1〉：\<手机\_1\>，先确认【金额_1】的保证金
→
还原后请回电王建国：139 1234 5678，先确认125 万元的保证金
