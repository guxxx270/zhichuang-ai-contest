## 二、名单透露的评审口味

1. **业务部门牵头的赢**。进终审的 4 个，推荐单位第一位全是业务/职能部门（客群发展、风险管理、财富平台、人力资源），技术研发部只做联署。技术研发部牵头的两个（10 蒙特卡洛定价、11 MCP 数据地图 Agent）技术含量不低，都只拿三等奖。
2. **题目写的是业务结果，不是技术手段**。"助力分支践行客户资产改善计划""赋能战略客户一体化经营"，句式多为"产品名——业务口号"；高频词：画像 / 标签 / 一本账 / 闭环 / 全景图 / 自动化 / 智能体。
3. **"最佳实践案例"看的是已经在用**。多数是平台、看板、自动化报告这类"公司自有数据 + AI"的数据产品，隐含要求：真实运行、有结果数字。
4. **集团与子公司同赛**。海通恒信（融资租赁子公司）也在名单里；国泰君安期货是国泰海通的子公司，公司赛的口味大概率延续集团赛，好作品有机会往上送——"可复制到集团其他子公司"是加分叙事。
5. 跨部门不是决定因素（终审 4 个里有 2 个单部门），但 13 个里 8 个是两部门以上联队。

## 三、对「需知」的启发（按性价比排序）

1. **把主角换成业务部门（零代码，改文案与 PPT）**。现在的摘要是技术部视角（"告诉技术部要和业务确认什么"）。改成：投资经理 / 研究员自己把三句话扔进去，五分钟答完确认清单，拿到能点的原型——"业务自己就能把需求说清楚"是一层价值，技术部省时间是第二层。PPT 首页放业务场景，规则引擎、四层知识、BMAD 这些放到"落地与安全"页。
2. **借"六步法"包装（零代码）**。1 号作品是"六步法数字化平台"——方法论 + 工具。需知恰好六项技能（问清 / 写单 / 估量 / 定架 / 出样 / 对账），可以包装成"需求分析六步法"：方法本身没工具也能推广（可复制 20 分），需知是它的数字化载体。标题备选："需知——需求分析六步法 AI 工作台：一堆话进来，一份能开工的需求出去"。
3. **交一份"试运行成绩单"（流程，需要真实需求）**。从现在到 10/15，把技术部真实进来的需求（脱敏后）走一遍需知，台账记：需求数、追问条数、业务采纳率、出稿时长、估算与实际人天偏差。PPT 上用"试运行 N 周、N 条真实需求"替代"回测过"，同时拿真实环境 Demo 的 +5。
4. **台账升级为"需求一本账 + 经营看板"（小改动）**。借 13 号"一本账"、7 号"闭环"、12 号"指标分析"的思路：台账记录每条需求从受理到交付的全程，对账环节回写实际工时校准估量；再加一页看板（各部门需求量、平均澄清轮次、估算偏差、AI 协同省时）。这一步把需知从"工具"变成"数据产品"，正好贴赛道口味。
5. **定架加"数据地图"（小改动）**。借 11 号"MCP 数据地图"：system_catalog.json 补数据域 / 接口 / 负责人字段，分析结果里明确"本需求涉及 3 个系统，2 个接口可复用，1 个需新建，数据来自柜台系统 X 表"。摘要里"数据从哪取"已经列为痛点，这一步是把它兑现。
6. 顺带：三个终审作品是画像/标签类，需知的估量 + 定架输出可以在 PPT 里以"需求画像卡"（类型 / 复杂度 / 涉及系统 / 合规敏感度 / AI 可协同度）的形式呈现，不必新写功能。

不建议做：把系统目录真的做成 MCP 服务、给提需求的人做画像——前者时间不够，后者有监控感。
