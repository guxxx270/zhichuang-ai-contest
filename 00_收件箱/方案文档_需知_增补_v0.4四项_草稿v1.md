## 一、四项能力一句话

| # | 能力 | 一句话 | 主要对应评分维度 |
|---|---|---|---|
| 1 | **追问记忆**（问过的不再问） | 同一提出方上次答过的口径，下次同类需求直接沿用并标 🧠，不再问；口径变了改一下，记忆随之更新 | 业务价值（澄清轮次↓）、创新 |
| 2 | **模型调用审计** | 每一次大模型调用落一行：用途、渠道、网关主机、模型、耗时、出站脱敏标签数、出站明文敏感项数（应为 0）、成败；不记正文 | 安全合规 |
| 3 | **沙箱策略一页** | 散在各处的白名单收成 `sandbox.yaml` 一个文件：模型协议、仓库协议与内网拒绝、凭据文件、问码工具白名单、接口监听与 Token、提醒开关；每条标代码执行位置，改文件即改行为 | 安全合规、可复制 |
| 4 | **REST API + MCP 接口** | 任何入口都能接：工单系统、公司 AI 平台里的智能体、Cursor / Claude Code 都能调问清 / 估量 / 定架 / 写单，同样进一本账 | 可复制推广、落地 |
| 附 | 催办摘要（默认关闭） | 一本账里待确认超期 / 已交付未对账 / 本周受理，只有数量、标题、天数；企微 `/摘要` 拉取；推送要三把锁同时打开 | 落地（流程闭环），不作卖点 |

## 二、可直接并入方案文档的段落

### 并入「4. 创新点」——第 1 条追问记忆，建议作为第 6 层

**6. 追问记忆，问过的不再问。** 业务对追问的答复（"比较基准 = 上一交易日结算价""客户版隐去内部字段"）按提出方（部门·角色）和部门两级记住；同一提出方再提同类需求，这些题直接沿用、在清单里标 🧠 并写进确认消息的"沿用上次口径"段，业务只需对有变化的说一声。记忆只存答复口径，不存原话与客户信息；命中次数进看板（"记忆省问"）。评测集 20 条平均追问 10.6 条，是首次；第二次起同提出方的追问数随记忆累积递减——这是通用 AI 写 PRD 工具没有的：它们每次都从零问起。

### 并入「5. 技术方案」——加一段"接口"

**接口**：除网页与企业微信外，需知提供 REST API（`/api/v1/analyze`、`/clarify`、一本账 CRUD、看板、审计、沙箱策略）与 MCP 服务（`xuzhi_clarify` / `xuzhi_estimate` / `xuzhi_architect` / `xuzhi_spec` / `xuzhi_ledger` / `xuzhi_reconcile`）。工单系统可在受理环节直接调用；公司 AI 平台里的任何智能体、Cursor / Claude Code 等 IDE 可把需知当工具。接口默认只监听本机、对外必须配 Token，请求体不接受模型 Key，模型只用服务端配置；`polish` 默认关闭，规则引擎毫秒级、可复现。三个入口进的需求都记在同一本账上。

### 并入「7. 技术与落地可行性」——上线路径第三阶段改写

第三阶段接公司 AI 平台账号体系与工单系统：**工单系统通过 REST 在受理环节调用需知**，一本账与工单双向同步；AI 平台里的智能体通过 MCP 直接调用问清与估量。（可选附加：一本账的超期项可按需汇总提醒，默认关闭。）

### 并入「8. 可复制推广性」——加一句

工具层面除了"换三张表"，还有"任何入口都能接"：网页、企业微信、REST、MCP 四个入口共用同一条流水线和同一本账；分公司、子公司不必用需知的界面，把自己的工单系统或 AI 平台接上即可。

### 并入「9. 安全与合规管控」——整段建议改为

数据去向写在一个文件里、也写在界面上。所有访问边界声明在 `sandbox.yaml`：大模型调用先脱敏再出站、Key 只留会话、网关协议白名单；代码仓库只拉 http(s) 公网或公司托管仓、拒绝本机与内网地址、Token 走环境变量；凭据类文件（.env、*.pem、*secret*…）不读；原型在独立源沙箱 iframe 渲染；企微入口白名单、问码只放行只读三件套；接口默认只听本机、对外必须 Token；不接生产数据库、演示数据虚构；提醒默认关闭。「隐盾」页原样展示这份策略并标出每条规则在代码里的执行位置，改文件即改行为。**每一次模型调用记审计**：用途、渠道、网关主机、模型、耗时、出站提示词里的脱敏标签数、检出的明文敏感项数（应为 0）、成败，可导出 CSV——评审可以直接核对"进模型的东西是脱敏过的"。每次分析、答复、状态、对账、记忆写入一本账，可导出。

### 并入「6. 业务价值与成效」——指标表加一行

| 指标 | 现状 | 目标 | 怎么测 |
|---|---|---|---|
| 同一提出方第二次起的追问数 | 每次从零问（10～12 条） | 首次 10 条 → 第二次起 ≤ 6 条 | 一本账"记忆省问"累计命中 ÷ 需求数 |

### 并入「开源借鉴」一句

审计、沙箱白名单、多入口接口的设计参考了 OryxOS（Apache-2.0，Java Agent OS）的"强制审计 + 三类白名单 + REST/MCP 暴露"模式，仅取模式，未引入其代码。
