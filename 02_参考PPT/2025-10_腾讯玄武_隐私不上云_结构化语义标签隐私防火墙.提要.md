# 提要｜隐私不上云，模型放心用：通过结构化语义标签实现隐私防火墙

**来源**：QCon 上海 2025（2025-10）｜陈昱 博士，腾讯 玄武实验室 高级研究员｜28 页｜原文件名 `陈昱-隐私不上云，模型放心用：通过结构化语义标签实现隐私防火墙（终版）.pdf`
**一句话**：在用户与云端大模型之间加一层端侧"隐私防火墙"（HaS）：把姓名/电话/地址等替换成保持语义的结构化标签送云端，回答后再还原——**正对本赛"未脱敏数据不得上公网大模型"的红线**。
**注意**：PDF 内嵌字体缺字，文字提取有缺漏，看原件为准。

## 结构提纲
1. **背景与挑战**：大模型隐私泄漏风险三层——模型服务商（输入输出被记录、用于产品优化、跨境存储备份、运营人员可接触、删除延迟）；上下游（日志/索引带出敏感参数、知识库未脱敏暴露姓名邮箱电话、监控排障平台保留完整请求、分享链接截图外泄）；部署（前端暴露 API Key、租户隔离不足、白名单被诱导、跨会话串线、日志缓存未加密）。按 OpenAI 2025-09 使用分布（实用指导 29%、写作 24%、信息检索 24%、多模态 7%……）逐场景列泄漏点：写投诉/预约会带住址手机身份证、润色简历邮件会带姓名薪资客户名单、总结内部 wiki 会带工号账号 IP、上传票据截图会带人脸车牌二维码、技术求助会贴 API Key/Token/数据库连接串。引用国标《生成式人工智能个人信息保护技术要求》第 6 部分（输出阶段默认不展示已识别个人信息）与第 8 部分（供应链：向第三方提供前先去标识化/匿名化）。
2. **方案（HaS）**：典型案例——用户让模型把含姓名/生日/电话/邮箱/住址的信息整理成简历再翻译再查投递官网：端侧脱敏 → 云端处理 → 端侧还原。八项能力矩阵对比密码学方案、正则、匿名化、伪匿名化、PII-Redact、Freysa、Presidio：实时响应、端侧部署、**语义保持**（"2019"在手机号/年份/门牌号中语义不同）、**信息还原**、开集指定、**指代消解**（"李明"与"Liam"同一人）、**多轮对话**、**意图识别**（当模型需要真实实体才能作答——如"查腾讯投递官网"——反问用户是否可提供）；只有 HaS 八项全满足。

## 可借鉴点
- **合规红线的技术解法**：本赛通知明令禁止未脱敏客户信息上公网大模型，而实训又要用公司 AI 平台——方案里加一页"端侧脱敏 → 平台处理 → 端侧还原"的隐私防火墙，15% 安全合规分基本拿满，还能成为创新点。
- **国标引用**：写"符合监管及公司安全防线"时引用《生成式人工智能个人信息保护技术要求》比空喊"合规"有力得多。
- **按使用场景列泄漏点**的清单，可直接改成期货公司版本：客户开户资料、持仓、成交回报、内部财务、研报草稿……做成方案里的"数据分级与脱敏矩阵"。
- **能力对比矩阵**（我们 ✅ 全满足、别人 ❌）是很强的版式，可用在"创新性"页对比现有方案。
- 个人赛"工具赛道"点子：做一个"贴给大模型前自动脱敏"的小工具/浏览器插件，即插即用、明显提效，形态完全符合评分要求。
