# 提要｜从需求到投标：数据驱动的智能技术方案生成 Agent 实战

**来源**：AICon 北京 2025（2025-12）｜王志宏，商汤科技 大装置研发总监｜45 页｜原文件名 `AICon北京2025-王志宏-从需求到投标：数据驱动的智能技术方案生成 Agent 实战.pdf`
**一句话**：售前"读客户需求 + 读自家产品手册 → 可行性评估 → 方案文档 → 标书"的多 Agent 系统，讲得非常工程化（分阶段、代码片段、Token 成本），是"内容创作 / 智慧展业"场景的直接原型。

## 结构提纲（5 章）
1. **引言**：需求爆炸 + 高度定制 → 售前推进速度与产研评估速度不匹配；困境四点：海量数据（产品说明书、需求文档、法律模板、过往案例）、时间紧张（响应以天计）、知识孤岛、魔鬼细节（一个参数错误或合规遗漏就出局）。答案：由多个专家 Agent 组成的协同系统。数据四类：产品清单（OnePage、功能清单、白皮书、手册、API、价格）、技术能力、案例成果、需求拆解。产品经理视角的需求分析：定位、目标、用户与场景（售前顾问/项目经理/交付负责人）、输入输出、五个功能模块（需求理解、可行性评估、方案生成、风险提示、文档输出）。
2. **整体方案设计**："让 Agent 读所有文档，自动分析需求、匹配产品、写方案和标书"。
3. **关键技术**：阶段 1 文档分析——多格式解析与语义对齐、功能分级建模（功能概述 → 子功能 → 参数指标）、技术要素提取（选型、软硬件依赖、国产化兼容）、知识压缩与索引；一份 50 页文档约 30 万 Token、15 分钟；产品手册入知识库复用、需求文档按会话临时缓存；需求文档"灵魂 N 问"（周期、预算、硬件、信创、模型、小语种、稳定性、权限、旧系统、开源、外网、驻场……）；代码片段（LazyLLM + MinerU 解析 + Milvus + JsonExtractor 抽取 + 分层 node group）。阶段 2 产品与需求匹配：结合全局要求过滤、按产品分类切分需求、逐层匹配。后续阶段：方案生成与文档输出。
4. **问题及解决策略**、5. **总结展望**。

## 可借鉴点
- **"灵魂 N 问"清单**：把隐性的评估经验显性化成问题列表交给 Agent——个人赛"技能赛道"和"知识库赛道"都能用这个思路（把老员工的检查清单变成 Prompt/知识条目）。
- **分阶段流水线 + 每阶段"关键点"小结**的讲法，让评委看到工程而非演示。
- **Token 成本与耗时数字**（30 万 Token / 15 分钟 / 50 页）——评委会问成本，这是标准答法。
- **产品手册进知识库、临时文档走缓存**的区分——知识库治理的小细节，显得专业。
- 对期货公司："智慧展业"里机构客户的方案/投标响应、"内容创作"里的研报/路演材料生成，都可套这个骨架。
