# 提要｜MinerU：面向 Agent 时代的文档解析基础设施演进与实践

**来源**：AICon 上海 2026（2026-06）｜何聪辉，上海人工智能实验室 青年科学家｜41 页｜原文件名 `MinerU：面向 Agent 时代的文档解析基础设施演进与实践 何聪辉 .pdf`
**一句话**：开源文档解析引擎 MinerU（PDF/Word/Excel/网页 → 结构化文本/表格/公式）从 Pipeline 到解耦式 VLM 的技术演进——知识库的"第一道工序"，金融研报、合同解析场景直接相关；04_开源代码 候选。

## 结构提纲（5 章）
1. **背景**：文档解析四阶段（2015 传统 OCR → 2024 大模型团队觉醒/预训练语料 → 2025 百家争鸣/RAG 标配、OmniDocBench 成共识基准 → 2026 应用爆发/智能体办公，覆盖合同审查、研报分析）；两大场景：预训练数据管线、RAG 精准检索——"解析精度 = 答案可靠性"，解析误差会在分块、向量化中放大；领域特化：金融研报要求数据极高准确、法律合同要条理、医疗关乎生命。
2. **整体演进**：v1 Pipeline（2024 初）：布局检测 DocLayout-YOLO（比 LayoutLMv3 快一个数量级）、公式识别 UniMERNet（对标 Mathpix）、CDM 评测指标；预处理 → 内容解析 → 后处理 → 格式转换。v2.5 解耦式 VLM（2025-09）：OmniDocBench（9 类文档、4 版式、3 语言，被 Gemini 3 Pro/GPT-5/Qwen/DeepSeek 采用为基准）；两阶段架构（Stage I 低分辨率全局布局 + 阅读顺序，Stage II 原生分辨率局部识别，避免 O(N²) Token）；21 类细粒度标签 + PageIoU；ADR 原子公式解耦重组；OTSL 表格格式（28 → 5 种 token，序列长度 -50%）、旋转表格先矫正再识别；IMIC 推理一致性挖掘（三次推理不一致 = 难样本 → 人工标注）。数据驱动新范式。
3. **生态建设**、4/5. **展望**。

## 可借鉴点
- **"解析精度 = 答案可靠性"** 和"误差在分块、向量化中放大"——知识库赛道方案里讲"为什么先做解析治理"的论据。
- **金融研报 → 表格/公式/图表解析**是期货研究所文档的核心难点；MinerU 的表格（OTSL、旋转表）能力可直接写进技术方案。
- **评测先行**（先做 OmniDocBench 再优化模型）的思路可迁移：知识库赛道要求自备 10 道以上业务问题，本质上就是先建评测集。
- 与商汤那份形成配合：商汤在代码里就是用 MinerU 做 PDF 解析——两份 PPT 可互相印证"解析 → 抽取 → 检索"链路。
- 作为二开候选：开源、活跃、国产团队；许可证、GPU 需求、部署方式待评估。
