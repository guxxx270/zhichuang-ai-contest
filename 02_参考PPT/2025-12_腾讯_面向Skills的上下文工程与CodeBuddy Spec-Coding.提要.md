# 提要｜面向 Skills 的上下文工程与 CodeBuddy Spec-Coding 的结合实战

**来源**：AICon 北京 2025（2025-12）｜汪晟杰，腾讯｜44 页｜原文件名 `汪晟杰-CodeBuddy面向Skills的上下文工程.pdf`
**一句话**：从"提示词工程"到"上下文工程"再到"Skills"的方法论——为什么靠反复调措辞找"神奇提示词"不可持续，怎样用规范（Spec）、规则文件（AGENTS.md / SKILL.md）和技能包把最佳实践沉淀成可复用资产。**我们"技能化架构"的理论依据，也是个人赛技能赛道的写法参考。**

## 结构提纲
1. **Spec-Coding 与上下文工程难点**：提示词工程 FEIT（反复试错 / 加示例规则 / 特殊强调 / 调措辞）的问题——不同模型理解不一致、Context Rot；上下文工程 = 动态规划与维护最优输入 token 集合；"真正的差距不在模型，而在我们提供给它的信息生态系统"；角色从"文字工匠"到"AI 架构师"；三大支柱：规范驱动开发（蓝图）、智能体执行循环（引擎）、上下文高效系统（流水线）；传统编程 → 氛围编程（Vibe）→ 规约编程（Spec-Oriented）并存；SDD 四步 Specify → Plan → Tasks → Implement，"每小时规划省十小时返工"。
2. **CodeBuddy 落地上下文工程**：用工程纪律约束 AI——规则文件生态对比（AGENTS.md 2 万+ 开源项目采用、Claude Code Skills 技能包、GEMINI.md、Copilot instructions、CodeBuddy.md）；"规范即合约"。
3. **Agent Skills 实践路径**：技能包 = SKILL.md + 脚本 + 资源；按需加载；沉淀团队最佳实践。
4. **企业落地指南**、5. **2026 展望**。

## 可借鉴点
- **"技能 = SKILL.md + 脚本 + 资源"的形态**：我们的早读 / 百事通 / 写作 / 脱敏四项技能都按这个形态打包，每个技能单独可交付——个人赛技能赛道要求"结构清晰、泛化强、易复用"，正是 Skill 的定义。
- **提示词工程 → 上下文工程 → Skills 三阶段图**：方案里用来说明"为什么不是一个 Prompt 就完事"，显示技术深度。
- **"规范即合约"**：早读输出格式、百事通引用格式、写作模板都写成规范文件，模型只能在规范内发挥——对应安全合规与稳定性。
- **规则文件生态对比表**可作为"技术选型"页的素材（选择开放标准而非私有格式）。
