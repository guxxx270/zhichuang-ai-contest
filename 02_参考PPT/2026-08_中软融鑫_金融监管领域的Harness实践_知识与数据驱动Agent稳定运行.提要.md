# 提要｜金融监管领域的 Harness 实践：让知识与数据驱动 Agent 稳定运行

**来源**：AICon 深圳 2026（2026-08）｜于浩军，中软融鑫 总工程师｜36 页｜原文件名 `于浩军-金融监管领域的 Harness 实践：让知识与数据驱动 Agent 稳定运行.pdf`
**一句话**：以银行监管报送这个"不容 Agent 犯错"的场景为例，讲怎样把自由发挥的 Agent 改造成"照章办事"的受约束状态机——**和期货公司的合规/监管报送场景最接近的一份**。

## 结构提纲（3 章）
1. **应用场景**：监管报送四个硬约束——口径复杂（同一"贷款余额"在不同报表口径不同）、频度高（日/旬/月/季报，数十张报表上千指标）、零容错（报错是合规问题，会触发问询/通报/评级扣分）、强追溯（每个数字要能回答谁算的、按哪条口径、取哪张表）。通用 Agent 三大坑：口径漂移（两次算出 128.6 亿 vs 121.3 亿）、幻觉（引用不存在的文号）、不可解释（说不出取了哪张表）——共同根因是 Agent 在"自由发挥"。端到端四个环节：需求侧（监管要求 → 可执行逻辑）、报送前（数据初始化、指标自动计算、质量检核）、报送中（勾稽/同比/阈值复核、异常提示）、问题处置（根因分析、血缘追溯、工单流转）。四条硬要求：口径受控、数据可查、逻辑可溯、能力可复用。
2. **解决方案（AIR Harness）**：四个场景、一个底座、两类资产（知识资产：结构化口径条目库 + 术语本体 + 图数据库勾稽/血缘；数据资产：明细/指标/报表库 + 元数据 + 安全分级）。执行模型：把 ReAct 循环改成 **Plan → Guard → Execute → Verify → Trace** 五状态机，动作空间封闭（只能调已注册 Skill）、步数/Token/耗时上限、三处强制人工审批点（口径确认、数据补全、最终签发）、失败即停（fail-closed，不猜不跳过）。Skill 规格示例 `skill.yaml`：语义化版本、与治理资产硬绑定（metric_id / caliber_ref 指向知识条目而非文档）、输入输出契约、数值计算下推 SQL 引擎不经 LLM、幂等键、输出校验、回归用例。Agent 只做"编排与判断"，不做"取数与定义"。
3. **经验与展望**：双向驱动飞轮、五个真实踩坑、端到端实机演示、下一步三件事。

## 可借鉴点
- **场景选择的示范**：挑"零容错、强追溯"的合规场景，反而最能体现工程功力——期货公司的监管报送、合规检查、客户适当性审查都是同类场景，评委（含合规/风控领导）天然认可。
- **"更受约束的 Agent，而不是更聪明的 Agent"**——这句可直接做我们"安全与合规管控"页的标题。
- **五状态机 + fail-closed + 三处人工审批点**：这是"技术与落地可行性"和"安全合规"两页的现成架构图。
- **Skill 规格 yaml**：把口径"声明出来而不是提示出来"，个人赛"技能赛道"可以做类似的可复用 Skill 包。
- **三个坑的写法**（现象 → 根因 → 后果）非常适合方案里的"痛点"页，而且都有具体数字/例子。
