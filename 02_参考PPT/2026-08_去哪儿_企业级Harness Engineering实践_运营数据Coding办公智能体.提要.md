# 提要｜企业级 Harness Engineering 实践：运营、数据、Coding 与办公智能体工程化落地

**来源**：AICon 深圳 2026（2026-08）｜李佳奇，去哪儿旅行 基础架构负责人、技术总监｜41 页｜原文件名 `李佳奇-企业级 Harness Engineering 实践.pdf`

## 结构提纲（5 章）
1. **企业 AI 落地背景**：场景全景——AI 运营（商家服务、客服、日常运营、社媒、用户运营）、AI 数据（智能问数、商分、业务波动分析、经营分析）、AI 研发（开发、测试、运维）、AI 办公（企业龙虾 QPaw）。整体架构：入口（API/CLI、Web UI、飞书）→ 平台（QMoss 工作流、九章智能问数、QNova 数据分析、天弦 AI 研发、QPaw 个人助手、垂类平台）→ 基建（LLM 网关、MCP 网关、Skills 网关、Sandbox 调度、记忆平台）→ 模型（GPT/Claude/DeepSeek/GLM/Qwen）。四个平台各配一句成效：QMoss 纯自研 Java 工作流平台、机酒火服全业务线、数万级 PD 提效、亿级业务收益；QNova 商分/数分日常工具、数十垂直场景、全流程数据风控、一号位经营分析；QPaw 开箱即用、飞书深度融合、覆盖数百核心产运、企业级安全风控；天弦 覆盖小需求/复杂需求/系统升级、FE/RD/QA 全员、需求评审/异常修复/自主运维自动化、本地+云端 cc/codex 调度。
2. **AI 研发（天弦）**：核心观点"AI 研发不是生成代码，而是完成一次可验证的研发交付"——需求 → 代码 → 编译 → 提交 → 部署 → 日志 → 回写全链路；流程编排 Harness："AI 不直接自由发挥，而是在编排框架里执行"，Coding Agent 是执行引擎不是流程控制器；任务 → 编排 → 执行 → 验证；基础能力 Skills（Noah 部署、启动状态检测、日志分析、配置获取）。

## 可借鉴点
- **"入口 / 平台 / 基建 / 模型"四层整体架构图**——团队赛方案的"技术架构"页照这个分层画，评委一眼看懂；LLM 网关 + MCP 网关 + Skills 网关 + Sandbox 是 2026 年的标配基建词汇。
- **每个平台一句话 + 一个数字**（数万 PD、亿级收益、数百产运）的写法，适合我们"可复制推广性"页：讲清"已经覆盖多少人/多少场景"。
- **"可验证的研发交付"**这个定义可以迁移到任何场景："AI 不是给个答案，而是完成一次可验证的交付（报告、报表、工单）"。
- 对期货公司："企业龙虾"（个人助手 + 飞书/办公协同深度融合）对应本赛"办公协作"场景，是最贴近"人人都有智能体"口号的形态。
