# 提要｜从代码生成到研发闭环：AI Coding 在金融科技 SDLC 中的落地实践

**来源**：AICon 深圳 2026（2026-08）｜李渭宁，汇丰科技 内部开源负责人、内部开源技术委员会主席｜48 页｜原文件名 `李渭宁-从代码生成到研发闭环：AI Coding 在金融科技 SDLC 中的落地实践.pdf`
**一句话**：外资银行科技中心如何在强监管下把 AI Coding 从"个人提效"做成"企业级、可治理的 AI 软件工程"——度量、上下文、质量门禁、四层安全纵深，是"编程提效"场景最合规的范本。

## 结构提纲（4 章）
1. **企业落地 AI Coding 的挑战**：工具"各领风骚一个月"、90% 个人感知提效；方法论演进 Prompt → Context → Harness → Loop → Graph Engineering（每层回答一个问题：告诉模型什么 / 此刻看到什么 / 能调用什么 / 如何安全持续工作 / 多 Loop 如何协作）；AI Coding 是放大器（DORA 2025：好团队更强、差团队更快暴露问题）；规模化五项挑战：效率（度量团队产出而非代码行）、企业上下文、质量保障、安全治理、工程师体验。
2. **应对策略**：AI Software Engineering 总览——Outcome（LTTD↓、发布频率↑、变更失败率↓、MTTR↓）/ SDLC Flow（分析、设计、开发、测试、发布、运维全部 Agent 化）/ Surface（Copilot、Claude Code、OpenCode）/ Harness（企业上下文、治理策略、Skills & Tools、质量与证据）/ Foundation（内部 LLM 平台、执行沙箱、可观测与 Token 成本）。**度量四指标**（LTTD、PDPTPPY、CFR、MTTR）每个配"衡量什么 / 关键问题 / 更好意味着什么"。**Agent-ready 上下文**：代码库 OpenSpec、企业知识（Confluence/Jira、RAG as a Service）、内部工具（MCP & Skills）。**质量门禁四阶段**：需求（可验证的完成标准、TDD/BDD）→ 开发（单测覆盖、质量扫描、SAST/密钥扫描）→ 测试（功能/压力/渗透）→ 上线前（证据聚合、发布决策）；"更快的编码 ≠ 更低的标准"。**安全四层纵深**：可信身份与版本（SSO、签名包、禁止自动批准、禁止绕过策略）→ Hooks 与全局策略（工具调用前策略决策、Policy-as-Code、RBAC、高危命令人工审批）→ 沙箱（文件/网络/凭证/进程隔离）→ GenAI API 网关（Guardrails、DLP & PII）。
3. **案例与经验**、4. **回顾总结**。

## 可借鉴点
- **度量页**：LTTD / 发布频率 / 变更失败率 / MTTR 四指标——"业务价值与成效"要讲编程提效时，用这四个而不是"写代码快了 N 倍"，评委里的 IT 高管会认。
- **四层纵深防御图**：直接对应本赛"安全与合规管控 15%"，可改造为任何 Agent 的安全页（身份 → 策略 → 沙箱 → 网关/DLP）。
- **质量门禁"证据链"**（Requirements Evidence → Code → Test → Release）：讲"技术与落地可行性"时的可靠性论证。
- **五层方法论演进图**（Prompt/Context/Harness/Loop/Graph）：一页讲清我们方案处于哪一层、为什么不止是 Prompt。
- 汇丰是外资银行，"强监管下仍能规模化"的论证对期货公司有说服力。
